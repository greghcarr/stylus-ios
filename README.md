# Stylus iOS

iOS / iPad port of [Stylus](https://github.com/greghcarr/stylus), a C++17/JUCE
audio player. Hybrid architecture: SwiftUI app shell over a C++ static library
(`StylusCore`) that reuses the desktop project's analysis, library scanner,
`.styl` sidecar I/O, and Apple Music lookup verbatim, with an Objective-C++
bridge in between.

See [IOS_PORT_PLAN.md](External/stylus/IOS_PORT_PLAN.md) in the desktop submodule
for the full architecture and phased delivery plan, and [CLAUDE.md](CLAUDE.md)
for the iOS-specific architecture reference.


## First-time setup

Prerequisites:

- macOS with Xcode 16+ and Xcode Command Line Tools. The deployment
  target is iOS 18 (uses `onScrollGeometryChange` and other iOS 18+
  APIs); install the corresponding iOS 18 SDK via
  Xcode → Settings → Platforms.
- An iOS Simulator runtime if you want to run on the simulator
  (Xcode → Settings → Platforms → iOS Simulator).
- Homebrew. Used for:
  ```sh
  brew install cmake xcodegen
  ```

Cloning fresh:

```sh
git clone --recurse-submodules https://github.com/greghcarr/stylus-ios.git
cd stylus-ios
make                        # generates StylusApp.xcodeproj from project.yml
open StylusApp.xcodeproj    # then ⌘R in Xcode to build + run
```

If you cloned without `--recurse-submodules`:

```sh
git submodule update --init --recursive
```

## Build / run workflow

Day-to-day, work happens inside Xcode. The `Makefile` exists for the
xcodegen step and command-line verification.

```sh
make            # regenerate StylusApp.xcodeproj from project.yml
                # (run after editing project.yml; Xcode will prompt to Revert)
make build      # unsigned verification build for iOS device
make build-sim  # unsigned verification build for iOS Simulator
make clean      # wipe local build trees
```

A pre-build script phase inside `StylusApp.xcodeproj` automatically invokes
CMake to build `libStylusCore.a` for whichever SDK Xcode is targeting; you
don't need to invoke CMake manually.

## Pointing Stylus at your music

Stylus reads from a single user-picked folder anywhere the iOS document
picker can reach: a top-level "On My iPhone" folder (created in the Files
app), an iCloud Drive folder, or an external USB drive. The folder isn't
inside Stylus's sandbox by default, so the same files can be read by other
players, and uninstalling Stylus doesn't delete your library.

On first launch the app shows **Choose Music Folder...**. Pick the folder
once; Stylus persists a security-scoped bookmark and resumes the same
location on every subsequent launch.

The folder is scanned recursively. The scanner skips dot-prefixed files
(so `.styl` sidecars are read as metadata sources, not played as audio),
and accepts `mp3 / flac / wav / aiff / aif / m4a / aac / alac / ogg /
opus`.

## Submodule operations

This project pulls the Stylus C++ core in as a git submodule under
`External/stylus`. A submodule is a pinned reference to a specific commit
in another repo; the iOS repo does not auto-update when the desktop repo
moves forward. Pin bumps are deliberate so a desktop change can't
accidentally break the iOS build.

**Bump the pin to absorb desktop changes:**

```sh
git submodule update --remote External/stylus
git add External/stylus
git commit -m "Bump stylus submodule: <reason>"
```

**Check the current pin:**

```sh
git submodule status
```

A `+` prefix means the submodule has uncommitted changes vs. the pin; a
`-` means it's not yet initialised.

## Roadmap

- [x] **Phase 0** Desktop core extraction (in stylus repo, commit `e0a4e82`)
- [x] **Phase 1** Bridge `Stylus_LibraryCreate` + `Stylus_LibraryStartScan` +
      `Stylus_StylLoad`; SwiftUI `List` view; tap-to-play with `AVAudioPlayer`
- [x] **Phase 1.5** Folder picker with security-scoped bookmark so music can
      live in any shared location
- [x] **Phase 1.6** `LibraryCache` bridged for instant launches
- [x] **Phase 1.7** Per-file 15s scanner timeout, smaller batch size for
      smoother progress reporting
- [x] **Phase 2** Full `.styl` metadata + album art (thumbnail in track row,
      bpm + key alongside duration)
- [x] **Phase 3a** Swift `PlayQueue`, AVAudioEngine-based `AudioPlayer`,
      bottom transport bar, auto-advance on track end
- [x] **Phase 3b** Full-screen Now Playing sheet (large art, scrubber,
      big transport)
- [x] **Phase 3c** `MPNowPlayingInfoCenter` + lock-screen art + remote
      commands (lock screen, Control Center, AirPods, scrub)
- [x] **Phase 4** All Songs / Artists / Albums / Search with drill-down
      navigation. The default iOS tab bar is hidden in favour of a tap-
      able title chevron (UIKit-backed `UIButton` + `UIDeferredMenuElement`)
      so the bottom of the screen is reserved for the mini Now Playing
      bar. (Playlists deferred to Phase 7.)
- [x] **Phase 4.5** Podcasts folder + tab. Pick a separate podcasts
      folder; podcast episodes are excluded from All Songs / Artists /
      Albums and surfaced in their own tab grouped by show.
- [x] **Phase 5** Background BPM / key analysis. User-triggered via the
      trailing overflow menu; results write to `.styl` and refresh the
      in-memory library as tracks finish.
- [x] **Phase 6a** iTunes Search "look up missing artwork" library-wide
      action.
- [x] **Phase 6b** Edit Info sheet + per-track context menu (Play Next /
      Add to Queue / Look up on iTunes / Edit Info)
- [x] **Phase 6c** Skip-scan launch optimisation. After loading the
      cache we run a quick `FileManager` enumeration of the music +
      podcast folders (de-duped via a Set so files under both roots
      aren't counted twice); if the count matches the cache's track
      count, the slow metadata-reading scan is skipped entirely. The
      "Re-scan folders" menu item bypasses it on demand.
- [x] **Phase 6d** Custom Now Playing presentation. Single `sheetY`
      state drives a finger-tracking expand-from-bar / dismiss flow,
      with a collapsing artwork header (full-size at scroll-top,
      shrunk to ¼ pinned at the visible top through the collapse
      range, then continues scrolling normally). Auto-presents on
      `scenePhase = .active` so dynamic-island / lock-screen taps
      land users on the full sheet immediately. Splash screen +
      launch storyboard for a no-flash launch.
- [ ] **Phase 7** Drag-and-drop playlist editing
- [ ] **Phase 8** iPad NavigationSplitView, AirPlay, polish
- [ ] **Phase 9** (desktop side) Cable + Wi-Fi sync engine via libimobiledevice
- [ ] **Phase X** CarPlay - aspirational, gated on Apple's CarPlay Audio
      entitlement (paid Developer Program + Apple approval). May never ship.
